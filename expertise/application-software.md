# Application Software

My view: application software is where architecture becomes a **usable product** — APIs, services, and UIs that teams can operate, extend, and reason about.

I build backends and interactive frontends with a bias toward clear contracts and reproducible delivery:

* **Backend:** Java · Spring Boot · Go · REST · GraphQL
* **UI:** React · Qt / QML · Flutter · GTK4

The [Vehicle Configurator](../showcase_vehicle_configurator.md) shows a full vertical slice: Vue/Three.js UI, Java 25 / Spring Boot 4 API, and containerized deployment.

### Connectivity (application side)

Toward backends and the cloud I treat connectivity as application concern: **REST**, **GraphQL**, **MQTT**, **WebSockets**, and similar integration styles. These link services, UIs, and sometimes edge gateways.

Field buses and on-device protocols (e.g. **CAN**) stay under [Embedded Software](./embedded-software.md). Cloud-connected products usually need both views of connectivity — device reality *and* service contracts.

**Keywords:** Java · Spring Boot · Go · REST · GraphQL · MQTT · WebSockets · React · Qt / QML · Flutter · GTK4
